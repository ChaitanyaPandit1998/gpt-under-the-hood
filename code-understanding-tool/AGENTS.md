# Project Change Tracking

For each meaningful code or behaviour change, update `DEVLOG.md` with a dated
entry describing the outcome, validation actually run, known limitations, and
next steps. Extend the current entry for related work rather than duplicating it.

Distinguish automated checks, mocked browser tests, live provider experiments,
and human assessments. Do not claim that unrun checks passed. Never put API
tokens, credentials, private source, or raw sensitive prompts in the log.
